# Deepfall — project guide for Claude

(AGENTS.md holds the same guide for other AI agents; keep the two in sync when either changes.)

Thai fantasy gacha + dungeon-crawler browser game (inspired by "Surviving the Game as a Barbarian" and "Pick Me Up", but all names/characters original). Turn-based 4-hero battles with telegraphed enemy intents, branching dungeon floors, permadeath with revive, knowledge journal, lobby events. Owner talks in Thai; reply in Thai. Pixel-art images are generated by the owner (PixelLab / ChatGPT).

Play online (GitHub Pages, public repo, rebuilds automatically on every push to `main`): https://chaiyasanchaninphum-ship-it.github.io/Deepfall-BETA-/ (editor: `editor.html`).

## Layout
- `index.html` — game shell. `editor.html` — content editor (owner uses it to tweak data without spending tokens).
- `js/data.js` — loads `data/*.json`, applies the editor draft from localStorage (`deepfall_mod_v1`), `assetSrc()`.
- `js/engine.js` — all game logic (~600 lines). Only read the part you need (grep for the function).
- `js/editor.js` — generic JSON form editor + validation + image preview.
- `css/style.css` — shared styles.
- `data/` — ALL content. Prefer editing these over engine code:
  - `config.json` numbers (gacha rates/pity, prices, rewards, scaling, death/revive)
  - `heroes.json` heroes (stats, skills, hidden skill + unlock {type: allyFellSurvive | treasure n}, talk lines at affinity 3/6)
  - `skills.json` hero skills + enemy moves, effect lists (`fx`). Effect types are documented in its `_help`; engine: `runFx()`, `execIntent()`
  - `enemies.json` enemies + AI (`seq`, special `cult` / `boss` with p1/p2)
  - `encounters.json` enemy groups per floor, boss group
  - `events.json` dungeon events (data-driven choices/fx), room texts, lobby event texts
  - `story.json` intro, journals per floor, boss texts
- `assets/` — PNGs named exactly as the editor's Images tab lists (hero_01.png, hero_01_portrait.png, enemy_01.png, boss_01.png, bg_*.png, icon_*.png, room_*.png). Missing files fall back to emoji.
- `tools/playtest.py` — headless-Chrome bot: random full runs + boss win-rate by level/team. `tools/fmt.py` — compact JSON formatter (always run after editing data).

## Common jobs (cheap paths)
- Owner pastes editor export (`=== data/<file>.json ===` blocks): for each block `python3 tools/fmt.py --stdin <file> < block.json`, then playtest, commit, push, republish.
- New hero/enemy/skill/event: edit only the data file(s); engine changes only for genuinely new mechanics (new fx type, new AI special, new room type).
- Owner sends images: PixelLab character export (zip/png+json) → `python3 tools/import_pixellab.py <zip> hero_XX` (writes still, portrait, idle strip, keeps source in assets/src/) then add the printed `"anim"` to the hero/enemy in data. Backgrounds: 960×540, quantize to 256 colours (≈350 KB each), originals' README in assets/src/backgrounds; which dungeon floor uses which file is `config.dungeon.backgrounds`. Other images: resize to the listed size with nearest-neighbour, transparent background, save into `assets/` with the exact name.
- Balance check: `python3 tools/playtest.py --runs 0 --boss 10 --levels 3,6,10`.

## Ship
1. `python3 tools/fmt.py && python3 tools/playtest.py --runs 2 --boss 4 --levels 6` (must print `ERRORS: none`).
2. Commit + push to `main`.
3. Republish the artifact (slug `6b76cb51-2669-4824-aaac-ef5aecf39417`) with `publish_files`, sending index.html, editor.html, css/, js/, data/, assets/ (every file, same relative paths).

## Rules
- Game data must load via fetch, so the game only runs from a web server (artifact / GitHub Pages / `python3 -m http.server`), not file://.
- No alert/confirm/prompt (blocked in the artifact frame) — use in-page dialogs.
- Keep keys starting with `_` (`_help`, `_note`) — they are shown as help in the editor and ignored by the game.
- Save format is in localStorage `deepfall_save_v1`; don't break old saves (add fields with defaults).
